# Changelog

All notable changes to Memora Core are documented in this file.

The format is loosely based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
release notes for tagged versions are auto-generated by
[goreleaser](https://goreleaser.com/) from the commit log between
tags. This file captures larger themes per release plus any details
that the auto-generated notes would lose.

The project follows [Semantic Versioning](https://semver.org/) — see
[`docs/dev-docs/releasing.md`](./docs/dev-docs/releasing.md) for the versioning policy.

## [Unreleased]

### Security
- The Gemini embedding provider sent its API key as a URL query parameter
  (`?key=`), and Go transport errors print the full URL. The key could
  reach vector-search error responses (HTTP and MCP), server logs, and
  `embed_failed` ledger entries (#6165). The key now goes in the
  `x-goog-api-key` header. Provider transport errors drop URL query
  strings. Search returns a fixed `embedding provider error` message
  and logs only the redacted detail. Ledger entries are redacted too.
  **Operators who ran Gemini embeddings should rotate the key** if logs
  or the ledger may hold it.
- Edits that re-chunk a Memory to fewer cells now delete the removed cells,
  their vectors and their content blobs (#6037). Before, the cell rows and
  content stayed, so `GET /v1/workspaces/{ws}/memories/{id}`, the console
  and the content store kept serving text that had been edited out, and
  changed cells left their old-text vector behind (it could surface in
  vector recall). Leftover cell rows, their content and stale vectors are
  removed the next time such a Memory is edited; content blobs that earlier
  versions wrote under never-stored cell IDs are not found by that cleanup.
- Console session cookie is `Secure` behind TLS-terminating proxies (#6033).
  New `server.ui_cookie_secure` (`MEMORA_UI_COOKIE_SECURE`): `always`,
  `never` or `auto`. **Default is `always` on a non-loopback bind** and
  `auto` (previous behaviour) on loopback. A `Secure` cookie is named
  `__Host-memora_session` and the console sends HSTS. The Helm chart sets
  `always` when `ingress.tls` is set (`uiCookieSecure` overrides). If you
  serve the console over plain HTTP on a non-loopback address, set
  `ui_cookie_secure = "auto"`, or login will loop; existing sessions must
  sign in again.
- The dev and federation docker-compose stacks publish on `127.0.0.1` only
  and require API keys from a `.env` (#6032); no keys are committed.
- Cross-tenant access closed on every ID-addressed primitive (#4373, after
  #4228/#4229): Update/Patch/Append, cell reads, pin deletes, edge unlink,
  edge cascade-forget, MCP `memora_lookup` and Recall lookup mode now
  return not-found for another workspace's IDs. Update's CAS conflict
  check is scoped too, so a foreign ID no longer answers 412 with its
  head watermark.

### Changed
- Agents are registered per workspace: `memora_agents` is keyed
  `(workspace_id, agent_id)` (sqlite migration 0009, postgres 0006), so
  the reserved agents (auto-link, legacy shim, console) and any shared
  agent ID such as the CLI default are registered in every workspace
  that uses them. Before, the first workspace claimed the ID node-wide
  and others returned 404 (#6154). Both stores back-fill the reserved
  agents into existing workspaces at startup.
- Hybrid recall and search fuse the keyword and vector rankings by
  reciprocal rank fusion (`internal/rank`, k=60) instead of
  `0.7·cosine + 0.3·keyword`. `weights` now scale each ranking's votes
  (default equal). Vector results list each Memory once, with its best
  cell (before, the last matching cell won). A failing side is reported
  in the new `degraded` response field (`vector_unavailable`,
  `keyword_unavailable`) instead of being swallowed. Pure vector mode
  returns an error, not an empty list, when it cannot embed the query.
- Keyword recall and search use a full-text index: SQLite FTS5 with BM25
  ranking, and Postgres `tsvector` + GIN with `ts_rank` (postgres
  migration 0005). The index covers every Memory, replacing the
  substring scan of the 500 newest. Matching is by word, with English
  stemming; query punctuation and operators are plain text. New
  `MetadataStore.SearchKeyword` (adapter API).
- **BREAKING (IDs)**: new workspaces, collections, memories, cells, edges,
  watermarks, ledger entries and pins get canonical lowercase UUIDv4 IDs
  instead of prefixed ULIDs (`mem_01H…`). The API, MCP and type validators
  reject any other ID form with `400 invalid_input` (MCP: `-32602`) naming
  the field, e.g. `memory_id must be a UUID`. `types.NewID()` takes no
  prefix; `types.ParseID(field, id)` replaces `MustHavePrefix`; the
  `oklog/ulid` dependency is gone. `federation.federation_id` must be a
  UUID. Agent IDs are UUIDs too (`Memora-Agent-Id`, MCP `agent_id`,
  `written_by_agent_id`); names go in `display_name`. The sentinel agents
  have fixed UUIDs (`AgentLegacyVibeflowID`, `AgentSystemAutoLinkID`) and
  the CLI's default agent is `c1a0e5d2-7b3f-4a6e-9d8c-1f2e3a4b5c6d`.
  Synthetic `parent_of` edges from the vibeflow shim get persisted UUIDs
  (sqlite migration 0007, `memora_synthetic_edges`) and are recognised by
  the view's `is_synthetic` column, not an `edg_synthetic_` prefix.
  Existing prefixed data is not migrated: no release shipped with it,
  so start with an empty database. `serve` and `mcp` refuse to start on
  a metadata store holding a prefixed workspace ID (see
  docs/user-docs/operations.md, "Upgrading from Prefixed IDs").
- **BREAKING (identity)**: `anthropic_session`, `oauth_agent` and
  `oidc_agent` no longer require the agent ID to equal a derived string or
  token claim. They implement the new `adapter.IdentityKeyer`: the proven
  identity is mapped to a UUIDv4 agent ID minted on first sight (new
  `MetadataStore.ResolveIdentityKey`, adapter API) and returned as
  `agentId` from MCP `initialize`. `identity.DeriveAnthropicSessionID` is
  replaced by `identity.AnthropicSessionKey`.
- **BREAKING (adapter API)**: `MetadataStore` gains
  `DeleteCellsFrom(ctx, workspaceID, memoryID, fromSeq)` (#6037); see
  `pkg/adapter/compliance.DeleteCellsFromContract`.
- **BREAKING (adapter API)**: `MetadataStore.UpdateMemory`, `AppendMemory`,
  `PatchMemory`, `GetCells`, `DeletePin` and `GraphStore.Unlink`,
  `CascadeForget` take `workspaceID` immediately after `ctx`, matching
  `ForgetMemory` and `GetAgent`. Third-party adapters must add the
  parameter and scope their queries by it; `pkg/adapter/compliance` is
  updated. MCP `memora_unlink` now requires `workspace_id`.
- **BREAKING (wire API)**: Imprint, Update, Patch, Append and Forget
  responses return the Memory's identifier as `id` instead of
  `memory_id` (REST and MCP), matching the `id` field on Memory and
  Workspace objects. Request bodies, query parameters and Recall hits
  (`memory_id`) are unchanged.
- **BREAKING (Helm chart)**: values key `primary.driver` is now
  `metadata.driver`, matching the `--metadata-driver` flag. The chart now
  refuses to render unless `apiKey` is set or `allowNoAuth: true` is set
  explicitly, and its liveness/readiness probes exec `memora-cli health` /
  `memora-cli ready` so they authenticate with the configured key.
- Helm chart: `ingress.*` values now render a `networking.k8s.io/v1`
  Ingress; the `serviceMonitor.*` values, which no template ever used, are
  removed until `/metrics` exposes real metrics.
- **BREAKING**: Retired monolithic `PrimaryStore` interface in favor of
  five dedicated adapters: `MetadataStore`, `ContentStore`, `GraphStore`,
  `VectorStore`, `LedgerStore`. CLI flag `--primary-driver` is now
  `--metadata-driver`; env var `MEMORA_PRIMARY_DRIVER` is now
  `MEMORA_METADATA_DRIVER`. Third-party adapters that implemented
  `PrimaryStore` must migrate to `MetadataStore` (tabular CRUD) and
  optionally `GraphStore` (edges / traversal). See updated
  [`docs/dev-docs/adapter-authoring.md`](./docs/dev-docs/adapter-authoring.md).
  **Note**: This is an interface refactor only — the storage layout is
  unchanged. The MetadataStore legacy columns (`memora_memories.content`,
  `memora_cells.text`) remain authoritative. ContentStore is a dual-write
  target. The column-drop migration is tracked for v1.0; operators
  performing deletion/erasure must continue to address the MetadataStore
  columns directly until then.
- Service layer graph methods nil-guard `GraphStore` — deployments
  without a graph backend degrade gracefully (forget skips cascade;
  explicit graph ops return 501 `capability_unavailable`).

### Added
- Recall and search hits carry their data: `matched_text` (the matching
  Cell's full text, with `cell_id` and `cell_index`), `created_at`, and
  with `include_content` the Memory's `content` (capped by
  `max_content_bytes`, default 64 KiB, at most 1 MiB, cut on a UTF-8
  boundary, flagged `content_truncated`). `include_cells` is now
  honoured. Hits are loaded with two batched store calls whatever `k`
  is, instead of one `GetMemory` per hit. New
  `MetadataStore.GetMemories` and `GetCellsForMemories` (adapter API).
- Node identity: `[node] id` / `name` (`MEMORA_NODE_ID`, `MEMORA_NODE_NAME`).
  Without config the node mints a UUIDv4 on first start and keeps it in
  the metadata store (new `MetadataStore.EnsureNodeID`; sqlite 0008,
  postgres 0004). `memora-core node id` prints it. Federation peers are
  keyed by `node_id`, which every `[[federation.peers]]` entry now
  requires. `federation_id` is an optional UUIDv4 cluster label, and
  `memora-core federation init` is removed.
- Node-wide search: `POST /v1/search`, MCP tool `memora_search` and
  `memora-cli search` query every workspace on the node, or those in
  `workspace_ids`, in keyword, vector or hybrid mode. Hits carry
  `workspace_id`. In `multi-tenant` mode `/v1/search` requires the
  `X-Memora-Workspace` header (400 `missing_workspace` without it; the
  header must be a UUID) and stays inside that workspace. `memora_search`
  requires `workspace_ids` (#6159). This is a scoping aid, not tenant
  isolation: holders of the shared API key can read every workspace.
  `adapter.VectorQuery` gains `WorkspaceIDs`
  and `AllWorkspaces`; a query with no scope is now invalid input
  rather than matching nothing.
- Opt-in async embedding (`embedding.async`, `MEMORA_EMBEDDING_ASYNC`,
  `serve --async-embed`; default off). Writes return once their Cells are
  stored and the in-process embed pool fills in vectors; imprint responds
  `recall_ready: false` and the Memory flips to ready when every Cell is
  embedded. Re-embed/skip counts match the inline mode, `auto_link: false`
  is honoured, and shutdown drains the queue before closing the stores.
- Cross-platform release pipeline (`.goreleaser.yaml` + `.github/workflows/release.yml`):
  cross-compiles to linux/darwin/windows × amd64/arm64, generates
  SPDX SBOMs via syft, signs every checksum and Docker manifest via
  cosign keyless (Sigstore), pushes multi-arch images to GHCR, and
  auto-publishes to the Homebrew tap and Scoop bucket when their
  tokens are configured. See [`docs/dev-docs/releasing.md`](./docs/dev-docs/releasing.md).
- F4 async embed pool: batching, retry-with-backoff, ledger
  `embed_failed` on permanent failure, recall_ready flip when all
  cells embed, in-flight cell dedup, plus the canonical 25-cell moat
  test that pins the patch-skip economic property.
- SQLite PrimaryStore: `FlipRecallReadyIfAllEmbedded` method (atomic
  single-statement check + flip); compliance suite test covers the
  partial / full / idempotent / zero-cells edges.
- MCP stdio transport: API-key handshake on `initialize`
  (constant-time compare, ErrCodeUnauthorized=-32001). Every
  non-initialize method requires a prior successful handshake when
  auth is enabled — including `ping` (no probe-without-key).
  `memora-core mcp` reads `MEMORA_API_KEY` and logs an enabled/
  disabled banner mirroring the HTTP serve path. New
  `internal/mcp/server_test.go` covers the handshake, dispatch
  round-trip, and frame-parsing edges.

### Changed
- VectorStore (`internal/store/sqlitevec`): acceptance criteria updated
  to match v0.1 reality — pure-Go brute-force cosine scan
  (`SupportsANN=false`) instead of `vec0` extension. vec0 requires
  `CGO_ENABLED=1` which conflicts with the zero-CGO cross-platform
  build. Performance is equivalent for v0.1 corpus sizes (<100K
  vectors). vec0 integration deferred to v0.5. See
  [`docs/dev-docs/architecture.md`](./docs/dev-docs/architecture.md#vectorstore-performance-trade-off).

### Known issues (tracked)
- macOS darwin binaries are unsigned; first run triggers a Gatekeeper
  warning. Notarization deferred pending Apple Developer Program
  enrollment.
- Windows binaries are unsigned; SmartScreen warning on first run.
  Code signing deferred.
- MCP stdio: agent_id is caller-supplied within the API-key trust
  boundary — per-connection IdentityProvider verification + agent_id
  pinning tracked as a follow-up issue.
- MCP WebSocket transport deferred to v0.3 (browser-first MCP
  ecosystem expected to mature; current OSS clients use stdio).
- SQLite LedgerStore `Query()` has a `ts` TEXT-column scan bug;
  Append works but Query fails. Tracked as a follow-up; HTTP
  `GET /v1/ledger` is affected and will return errors until the fix
  lands.
